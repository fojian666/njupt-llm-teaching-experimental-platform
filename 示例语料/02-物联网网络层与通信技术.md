# 物联网网络层与通信技术

> 本文为平台自带的原创示例语料，可自由修改替换。

## 一、网络层要解决什么问题

网络层位于感知层与应用层之间，负责把感知层采集到的数据**可靠地送出去**。它面对的困难并不只是"传得远"：节点可能埋在农田、装在配电柜、贴在运送中的集装箱上，于是**功耗、覆盖、成本、移动性**四件事必须同时权衡。也正因为这个场景与手机上网差异很大，物联网才发展出一整套与蜂窝网、Wi-Fi 并行的小众通信技术。

## 二、短距离无线通信

### 2.1 蓝牙与低功耗蓝牙

经典蓝牙面向连续音频流这类稳定连接；低功耗蓝牙（Bluetooth Low Energy，BLE）则把重心放在极短的连接窗口与广播机制上——设备大部分时间在休眠，只在广播间隔醒来发一小段数据。智能手环、电子价签这类"一次发几个字节、但要撑几个月"的场景，用的基本都是 BLE。

### 2.2 ZigBee 与 IEEE 802.15.4

ZigBee 建立在 IEEE 802.15.4 之上，速率只有几百 kbps，换来的是低功耗与**自组网**能力：节点可以自动组成网状（mesh）结构，某条链路断了能绕行另一条。它适合节点数量多、单点数据量小、需要多年免维护的场合，例如楼宇照明控制与工业现场仪表。代价是跨厂商互通性历来是痛点，实际项目里往往整网采用同一套生态。

### 2.3 Wi-Fi 与 Wi-Fi 6

Wi-Fi 的优势是**带宽与生态**：部署门槛低、设备普及、协议栈成熟，摄像头、网关、服务机器人这类需要传图片或视频的设备大多走 Wi-Fi。它的短板同样明显——功耗偏高，且接入点能承载的并发设备数在面对成百上千个传感器时并不宽裕。Wi-Fi 6 引入的调度机制改善了高密场景下的并发表现，让它在工业与园区场景重新有了位置。

## 三、低功耗广域网络

### 3.1 LoRa

LoRa 采用扩频调制，用极低的速率换取极远的链路预算，在郊区视距条件下可达数公里乃至十几公里。它可以使用免许可频段搭建**私有网络**，因此特别适合企业自建、覆盖范围明确、数据量很小的场景，例如水表、气表、农业土壤监测。代价是速率低、且组网与运维需要自己负责。

### 3.2 NB-IoT

NB-IoT 工作在运营商授权频段，终端直接接入蜂窝网络，不需要单位自建基站。它的特点是**覆盖增强、低功耗、大连接**：信号能穿透地下室与厚墙，终端靠电池可工作数年，单小区可承载大量连接。代价是数据速率低、时延较大，且必须依赖运营商的网络覆盖与资费方案。

## 四、协议适配与网关

设备侧的通信协议与业务侧并不一致：设备多说 MQTT、CoAP 这类轻量协议，业务系统则习惯 HTTP 与消息队列。中间必须有一层网关做协议转换、数据规整与断线缓存。工程上最容易出问题的地方恰在这里——**弱网断连、时区与时间戳、字段口径**，这些在实验室里都不出现，一上线就集中爆发。设计网关时把"断网期间本地缓存多久、恢复后如何补传、重复数据如何幂等"这三件事想清楚，比选什么协议更重要。

## 五、选型建议

选型可以从三个问题倒推：**数据量有多大**（决定速率下限）、**节点能取到电吗**（决定功耗预算）、**覆盖由谁负责**（决定自建还是租用运营商网络）。三者一旦确定，可选集合通常就只剩一两个。需要提醒的是，同一个项目里混用多种通信技术是常态而非例外：短距离用 BLE 或 ZigBee 把数据汇聚到网关，再由网关通过 NB-IoT 或 Wi-Fi 回传，这种分层组合往往比强求一种技术"通吃"更划算。
