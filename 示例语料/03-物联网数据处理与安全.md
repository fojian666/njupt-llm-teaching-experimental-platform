# 物联网数据处理与安全

> 本文为平台自带的原创示例语料，可自由修改替换。

## 一、从数据到决策的分层

物联网产生的数据量远大于人工能处理的数量，因此"采上来"只是起点，真正的价值在于**把它变成可执行的判断**。这一过程通常分成四步：数据清洗（去重、去噪、补缺）、特征提取（从时序或图像中抽出有意义的量）、建模分析（阈值判断、统计模型或机器学习）、动作反馈（下发指令或推送给责任人）。每一步都需要明确**谁来算**——在节点上算还是送到云端算，这个选择直接决定了系统的时延、功耗与运维成本。

## 二、边缘计算与云边协同

把全部原始数据都上传云端在多数场景下并不划算：带宽有限、时延不可控、且大量数据其实没有上传价值。边缘计算的思路是**让靠近数据源的一侧先做一次判断**——异常才上报，正常只留汇总值。这样做的收益有三个：降低回传带宽、缩短响应时延（对需要毫秒级联动的控制场景尤其关键）、减少云端存储压力。云边协同则是把两边分工写清楚：边缘负责实时与本地自治，云端负责长期存储、跨域分析与模型训练，并把更新后的模型下发到边缘。

## 三、常见的数据处理任务

时序数据最常做的是**异常检测**：设备振动、温度、电流这类信号在正常情况下有稳定的波动范围，偏离即预警。第二类是**预测性维护**：从退化趋势推断剩余可用寿命，把"坏了再修"变成"按需检修"。第三类是**多源融合**：单一传感器容易误报，把温度、电流、声音几个通道联合判断，误报率通常显著下降。第四类是**统计与可视化**：面向管理者的日报、热力图、排名，本身不复杂，但决定了系统是否被真正使用。

## 四、安全威胁模型

### 4.1 感知层威胁

感知层的最大特点是**物理可达**：节点部署在无人值守的现场，攻击者可以直接接触设备，拆机读取固件、替换节点、伪造标签都是现实威胁。此外，无源标签的通信可以被旁路窃听，标签克隆的成本也很低。

### 4.2 网络层威胁

网络层的典型攻击是**中间人**与**重放**：攻击者在网关与云端之间截取报文，或把录到的合法指令原样重发以触发动作。若报文未加密或未带序号与时间戳，这两种攻击都难以被发现。另一个常见问题是**弱口令与默认凭据**：大量设备出厂使用同一套管理员密码，一旦暴露在公网就会被自动化脚本批量接管。

### 4.3 应用层威胁

应用层面临的是传统 Web 与 API 的风险：越权访问、注入、接口未做频率限制等。物联网特有的地方在于**数据本身敏感**——设备数据往往能反推出人的作息、在家与否、生产节拍等信息，泄露的后果与普通业务数据不同。

## 五、防护手段

可落地的措施按优先级排序：**一机一密**，避免默认口令与批量共享密钥；**双向认证**，让设备与平台互相确认身份，而不只是平台验证设备；**传输加密**，链路层与传输层至少有一层加密；**固件签名与安全升级通道**，否则设备一旦存在漏洞就永久暴露；**最小权限与网络分段**，让设备网络与管理网络隔离，避免一个摄像头被攻陷就横向渗透到内网。此外，设备行为的**基线建模**很有价值：一个平时每小时上报一次的水表突然被高频唤醒，这种异常本身就是入侵信号。

## 六、隐私与合规

设备数据常能间接识别到具体的人，因此采集前就要想清楚**目的是什么、最小必要范围是多少、保存多久、谁能看**。工程上的对应动作包括：原始数据尽量在边缘侧聚合后再上传、敏感字段在入库前脱敏、对外提供的接口只返回到汇总粒度。这些事一旦系统上线再补，成本会成倍上升——设计阶段留好开关，比事后补救容易得多。
